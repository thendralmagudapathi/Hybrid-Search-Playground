            What is this tool for?
            
  
            It is for people who build search: site search, retrieval for RAG (retrieval-augmented generation), chatbots that answer from your documents, or support tools. Search quality decides whether the right text reaches the user or the language model.
            
  
            It helps you answer questions like:
            
  
              
    
            • Why was the wrong document retrieved? Click it and see exactly which words matched, how much each one counted, and what was missing.
              • 
    
            • Should I use keyword, vector or hybrid search? See all three side by side on your own text, with numbers (precision, recall, MRR, nDCG) instead of gut feeling.
              • 
    
            • How do I tune BM25? Move k1 and b and watch rankings change instantly, then export the settings to Elasticsearch, OpenSearch or Python.
              • 
  
            
  
            Rule of thumb: BM25 is great at exact things (names, error codes, version numbers, rare words). Vector search is great at meaning (paraphrases, synonyms, questions phrased differently). Hybrid usually gets the best of both, which is why most production RAG systems use it.

            How the scoring works
            

  
            BM25 (Lucene / Elasticsearch version)
            
  
            IDF(t)      = ln(1 + (N − n_t + 0.5) / (n_t + 0.5))
score(d, q) = Σ over query terms t:  IDF(t) · tf(t,d) · (k1 + 1) / (tf(t,d) + k1 · (1 − b + b · |d| / avgdl))
            
  
            N = number of documents, n_t = documents that contain the term, tf = how often the term appears in this document, |d| = document length in tokens, avgdl = average length. Each distinct query word is counted once.
            
  
            Worked example. 40 documents; "timeout" appears in 2 of them. IDF = ln(1 + (40 − 2 + 0.5) / (2 + 0.5)) = ln(16.4) = 2.80. A document of average length (so the length factor is 1) has "timeout" 3 times. With k1 = 1.2: 2.80 × 3 × 2.2 / (3 + 1.2 × 1) = 2.80 × 1.571 = 4.40. Had it appeared once: 2.80 × 2.2 / 2.2 = 2.80. Three times the word, but only 1.57× the score.
            
  
            Note: the Python library rank_bm25 (BM25Okapi) uses a different IDF, ln((N − n + 0.5) / (n + 0.5)), which can go negative, so it replaces low values with an epsilon floor. Its absolute scores (and sometimes its order) differ from Elasticsearch and from this tool. The exported Python script uses the Lucene formula so it matches.
            

  
            Cosine similarity (vector search)
            
  
            cos(q, d) = (q · d) / (|q| · |d|)
            
  
            Worked example. q = (1, 0), d = (0.6, 0.8). q · d = 0.6; |q| = 1, |d| = 1, so cos = 0.6. The models here return vectors of length 1, so cosine is simply the dot product.
            

  
            Reciprocal Rank Fusion (RRF)
            
  
            RRF(d) = Σ over result lists  1 / (k + rank(d))      ranks start at 1, k = 60 by default
            
  
            Worked example. Doc A is #1 in BM25 and #3 in vector: 1/61 + 1/63 = 0.01639 + 0.01587 = 0.03226. Doc B is #2 in vector only: 1/62 = 0.01613. A wins because both methods liked it.
            

  
            Weighted score fusion
            
  
            norm(s) = (s − min) / (max − min)          per list
hybrid  = α · norm(vector) + (1 − α) · norm(BM25)
            
  
            Worked example. BM25 scores 9, 3, 0 become 1, 0.33, 0. Vector scores 0.8, 0.6, 0.4 become 1, 0.5, 0. A doc with BM25 0.33 and vector 1 at α = 0.5 gets 0.5 × 1 + 0.5 × 0.33 = 0.67.
            

  
            Glossary
            
  
            
    
            Token
            One unit of text after splitting, usually a word. "ERR-504 again" gives the tokens err-504, err, 504, again.
            
    
            Stemming
            Cutting words to a shared root so different forms match: connected, connecting → connect.
            
    
            Stopword
            A very common word (the, is, my) that is ignored because it appears almost everywhere.
            
    
            IDF
            Inverse document frequency. Rare words get a high IDF and count more; common words count less.
            
    
            TF
            Term frequency: how many times a word appears in a document. In BM25 each extra repeat adds less.
            
    
            Document length normalisation
            Scaling scores down for long documents (controlled by b), since long texts contain more words by chance.
            
    
            Embedding
            A list of numbers (here 384 of them) that represents the meaning of a text. Similar meanings give similar lists.
            
    
            Cosine similarity
            How closely two embeddings point in the same direction, from −1 (opposite) to 1 (same).
            
    
            RRF
            Reciprocal Rank Fusion: combine rankings by adding 1 / (k + rank) from each list.
            
    
            Precision@k
            Of the top k results, the share that are relevant.
            
    
            Recall@k
            Of all relevant documents, the share that made it into the top k.
            
    
            MRR
            Mean reciprocal rank: 1 / position of the first relevant result (1 if it is first, 0.5 if second…), averaged over queries.
            
    
            nDCG
            Normalised discounted cumulative gain: rewards relevant results more the higher they appear; 1 = perfect order.
